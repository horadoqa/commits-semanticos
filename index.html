O que são commits semânticos?

Commits semânticos são uma forma padronizada de escrever mensagens de commit para deixar claro o que mudou e por quê.

O padrão mais usado é o Conventional Commits.

Formato
tipo: descrição

Exemplos

commits
feat: adiciona login com Google
fix: corrige validação do formulário
docs: atualiza documentação da API
refactor: simplifica serviço de autenticação
test: adiciona testes para usuários

Principais tipos

Cada tipo representa uma categoria diferente de alteração realizada no projeto.

Tipo Significado Exemplo
feat Nova funcionalidade feat: adiciona login
fix Correção de bug fix: corrige erro no cadastro
docs Documentação docs: atualiza README
refactor Refatoração sem mudar comportamento refactor: reorganiza serviços
test Criação/alteração de testes test: adiciona testes de login
chore Manutenção chore: atualiza dependências
perf Melhoria de performance perf: otimiza consulta ao banco
ci Integração contínua ci: adiciona pipeline de testes
build Build e dependências build: atualiza versão do Node
revert Reversão de alteração revert: remove nova autenticação

Por que usar?

O principal benefício é que o histórico do Git fica organizado e fácil de entender.

❌ Sem padrão 
ajustes
mudanças
correção
coisas novas
final
arrumei
✓ Commits semânticos 
feat: adiciona recuperação de senha
fix: corrige expiração do token
refactor: separa serviço de autenticação
test: adiciona testes de recuperação de senha
docs: documenta endpoint de autenticação
📖

Histórico legível

Facilita entender rapidamente o que aconteceu durante o desenvolvimento.

⚙️

Automação

Ferramentas podem analisar os commits e gerar changelogs automaticamente.

📦

Versionamento

Os commits podem ajudar ferramentas a determinar novas versões do projeto.

💡 Dica:

O padrão também facilita identificar alterações que podem quebrar a compatibilidade com versões anteriores.

BREAKING CHANGE

Quando uma alteração quebra a compatibilidade com a versão anterior, você pode indicar isso utilizando ! depois do tipo.

⚠️ Alteração incompatível

O ! indica que existe uma breaking change. 

feat!: altera formato da resposta da API

Exemplo

commit
feat!: remove suporte ao endpoint /users/old

Usando o corpo do commit

commit
feat: altera autenticação

BREAKING CHANGE: o token agora deve ser enviado
no header Authorization.

Usando com um alias Git

Se você está usando o alias git cm, pode transformar a criação de commits semânticos em um processo simples e rápido. 

$ git cm

Escolha o tipo do commit:

1) feat - nova funcionalidade
2) fix - correção de bug
3) docs - documentação
4) refactor - refatoração
5) test - testes
6) chore - manutenção
7) perf - performance
8) ci - integração contínua
9) build - build/dependências
10) revert - reverte um commit

Opção: 1
Mensagem: adiciona login com Google

feat: adiciona login com Google
🚀 Resultado:

O alias facilita o uso do Conventional Commits, evitando que você precise lembrar e digitar os tipos manualmente.
